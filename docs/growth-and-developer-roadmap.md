# Keep Video 下一阶段行动计划

更新日期：2026-10-24
状态：P0 代码与本地验收已完成，生产部署、站点级数据补齐及手机真机验收待进行；P1/P2 仍是方案。
用途：依据早期 GSC 与 Umami 数据安排产品、开发和验证工作。

## 1. 先做什么

**先测清并改善英文在线工具的真实下载结果，保留匿名使用；再用可选登录支撑 API 内测，最后接入复用同一套下载服务的 MCP。**

第一批只交付以下三件事，不同时重做首页、登录和下载架构：

1. 补齐解析、任务完成和文件交付的数据，并区分示例与真实链接。
2. 验证英文 `/app/` 的电脑和手机流程，修复最影响成功使用的问题。
3. 建立同一时间窗口的来源与结果报告，验证带 ChatGPT 标记的访问是否持续产生成功任务。

| 优先级 | 工作 | 完成后能回答的问题 |
| --- | --- | --- |
| P0 | 数据口径、下载漏斗、服务端结果统计 | 人来了之后，在哪一步成功或失败？ |
| P0 | 在线工具可靠性与移动端保存 | 真实链接能否顺利变成可交付文件？ |
| P1 | 英文与葡语内容修正、来源复盘 | 哪些页面与来源值得继续投入？ |
| P1 | 可选登录、账户归属、API 内测 | 是否有人愿意反复使用自动化下载？ |
| P2 | MCP 授权与工具适配 | Agent 工作流是否产生额外的持续使用？ |
| 暂缓 | 全站强制注册、大规模扩语言与页面、付费套餐、批量和 Webhook | 先验证需求与成本，再增加复杂度 |

本文没有授权部署、发送邀请、公开原始分析数据或创建第三方服务。实施涉及这些动作时另行确认。

## 3. 产品边界

| 用户 | 可以做什么 | 第一版不承诺什么 |
| --- | --- | --- |
| 匿名网页用户 | 低额度解析公开链接、选择格式、生成并保存文件 | 无限次数、所有平台或所有链接可用 |
| 登录网页用户 | 在授权范围内跨设备查看未过期任务、查看额度、管理 API Key | 永久保存文件、无限并发 |
| 获准内测的 API 用户 | 脚本解析、创建异步任务、查询、取消和获取文件 | 任意下载参数、批量任务、Webhook、SLA |
| MCP 用户 | 授权 Agent 调用同一套有限工具 | 无确认消耗无限资源、读取别人文件或向模型返回整段视频 |

- 网页首页、在线页、平台页和指南继续公开可索引；个人页面和私有接口保持鉴权与禁止索引。
- 在用户完成任务或主动进入开发者入口时介绍登录收益，不在普通工具页入口强制注册。
- 登录 Keep Video 不等于登录来源平台；不承诺解决来源登录、会员、地区或平台访问限制。
- 在线服务只处理公开且用户拥有或获授权的内容；不增加访客 Cookie 上传、绕过来源权限等能力。
- 保留 Vue、Node、容器和现有下载引擎，不为鉴权更换前端框架或迁移运行平台。

### P0-02：补齐真实下载漏斗

**交付：**前端交互事件、服务端权威结果及一个可复核的统计视图。Umami 故障或被拦截不能阻断下载。

| 建议事件 | 发生条件 | 记录方 |
| --- | --- | --- |
| `tool_view` | 工具页交互初始化完成 | 浏览器；与现有 PV 区分，不能重复当作 PV |
| `example_selected` | 用户主动选择示例 | 浏览器 |
| `parse_requested` | 服务端接受一次有效解析调用 | 服务端；被限流的请求另计 rejected |
| `parse_finished` | 解析实际收尾，带 success/error 结果 | 服务端 |
| `job_created` | 新任务持久化成功 | 服务端；幂等重放不重复计数 |
| `job_finished` | 下载与上传收尾，带 completed/error/cancelled 结果 | 服务端；重试按独立执行记录，不能重复发送同一终态 |
| `file_save_clicked` | 用户点击保存文件 | 浏览器；不等于设备保存成功 |
| `file_delivery_finished` | 一次响应流结束，记录状态、字节和 Range 范围 | 服务端；不等于完整文件已落盘 |

以上事件协议已实现；事件里的 cancelled 与业务 Job 的 paused 对应，不把统计结果名混作任务状态。

**最小字段：**时间、环境、渠道分类、页面语言、来源平台枚举、网页/API/MCP 客户端类型、示例标记、处理阶段、结果类别、耗时和文件字节数。服务端内部使用不透明关联 ID 去重；不向第三方发送可用于访问任务的 ID、用户/会话凭据或完整关联日志。

- [x] 区分 `example`、`user_input`、`unknown`；无法确认时不能自动当作真实需求。
- [x] 不发送完整视频 URL、标题、Cookie、Authorization、API Key、签名下载链接或原始错误日志。
- [x] 事件投递失败不阻塞业务；重放具有去重标识，停服务前的未投递记录有可控处理策略。
- [x] 关闭网页后任务继续执行，结果仍进入服务端统计；WebSocket 重连不重复生成任务或统计。
- [x] 报表保留统计缺失和 pending 数量，不能把没有终态的记录默认为成功或失败。
- [x] 多次保存与 Range 续传单独统计交付请求和传输字节；不要将多个 206 响应直接当成多个成功文件。

**指标定义：**

| 指标 | 计算方法 |
| --- | --- |
| 解析成功率 | 同一已收尾解析批次中，成功解析数 / 已收尾解析数；另报仍在解析与被拒绝数 |
| 任务完成率 | 同一创建批次中，completed / 已终态任务；error 与用户取消分别列出，pending/running 不消失 |
| 工具使用率 | 同一自有会话口径下，提交真实链接的会话 / 有工具页访问且可测量的会话 |
| 激活率 | 同一可测量会话批次中，至少有一个真实链接任务完成的会话 / 工具页会话 |
| 等待与执行耗时 | 分别记录排队、解析、下载/合并、上传时长；报告样本量及中位数/P95 |
| 单个完成任务资源成本 | 同一批次成功和失败尝试的总可归属资源成本 / 完成任务数；无完成任务时显示无法计算 |

按任务创建日追踪终态，允许跨日完成，不用“今天完成数 / 今天创建数”冒充同批次成功率。浏览器统计受拦截影响时，明确可测量范围；不将 Umami 访客 ID 与自有会话假定为同一个标识，也不新增隐蔽设备指纹。涉及会话关联、保留期和隐私说明时先完成评审。

**验收：**在受控环境完成正常、解析失败、取消、关闭页面、重连、重复请求、Range 下载和统计服务不可用等场景；内部任务清单与统计终态一一对账，隐私字段扫描通过。

### P1-02：接入可选登录与稳定任务归属

**交付：**Better Auth 登录、退出、会话管理，以及独立于会话令牌的账户/访客主体。

- [ ] 默认先接一个登录渠道，建议 Google；若内测对象明确以开发者为主，可改选 GitHub，不同时铺多渠道。
- [ ] 网页匿名功能继续可用；登录收益是未过期任务访问和开发者能力，不是来源平台解锁。
- [ ] 用稳定主体标识拥有任务和解析记录；禁止把 API Key、Cookie 或 OAuth token 原文用作 owner 或存储目录名。
- [ ] 登录时经用户确认，只认领当前已验证访客会话的任务；不可提交任意 guestId 认领，也不能认领其他账户任务。
- [ ] 认领后撤销旧访客对这些任务的访问，刷新或关闭旧 WebSocket 订阅，避免只改 HTTP 授权却残留事件泄漏。
- [ ] 退出、会话撤销及账户停用后及时撤销访问和相关订阅；不要用登录时的一次校验永久授权 WebSocket。
- [ ] 密钥、会话配置、回调地址和可信来源只在服务端配置；按官方集成保留 CSRF、Origin 和安全 Cookie 校验。

**存储默认方案：**单实例内测优先持久化 SQLite，先验证选定 Better Auth 适配器与容器运行时兼容。若启动时已确定多实例，则改用 PostgreSQL，不把数据库选择拖成整个平台重构。

现有会话与任务使用 JSON 文件，必须单独设计迁移：备份、暂停新任务并等待执行收尾、建立旧 owner 到新主体映射、事务导入、核对数量与文件授权，再切流。文件存储键与授权主体分离，不能因为改 owner 就盲目改写 R2 对象路径。保留既有私有文件和到期策略，不重新公开已过期资源。

**验收：**账户 A、账户 B、访客三方隔离；登录前任务可正确认领；退出后旧订阅不可继续读；数据库重启后授权一致；迁移失败可恢复。切流后若已有新写入，回滚必须保留或迁回这些写入，不能直接覆盖旧 JSON。

### P1-03：发布有额度的异步 API 内测

**交付：**版本化 REST API、API Key 管理、使用说明、用量统计；默认只对获准内测账户开放。

| 拟新增接口 | 作用 | 关键契约 |
| --- | --- | --- |
| `POST /api/v1/parse` | 解析公开链接 | 有时限与解析并发限制，返回不透明 parseId、过期时间及安全格式列表 |
| `POST /api/v1/downloads` | 创建任务 | 只接受本人未过期解析结果中的格式；返回 202、jobId 和状态地址 |
| `GET /api/v1/downloads/:id` | 查询任务 | 返回明确状态、结构化错误和文件有效期，不返回服务器路径 |
| `POST /api/v1/downloads/:id/cancel` | 请求取消 | 幂等；停止尚未完成时返回取消中，不能提前释放槽位 |
| `GET /api/v1/files/:id` | 获取文件 | 账户归属、有效期和权限校验，保留 Range 语义 |

接口是目标方案，不是当前已存在能力。解析如果不能在请求预算内稳定结束，再单独演进为解析任务；不要让调用无限等待，也不要盲目重试 POST。

- [ ] Key 支持创建、到期、撤销、最后使用时间；明文只在创建时显示，后端安全散列存储，不写日志和 URL。
- [ ] 服务端限定 Key 的权限上限，建议分开 `media:parse`、`downloads:create`、`downloads:read`、`downloads:cancel`、`files:read`；创建人不能自行超出账户授权。
- [ ] 创建任务要求幂等键，以“主体 + 操作 + 键”为范围；相同键相同参数重放同一结果，相同键不同参数返回 409。
- [ ] 幂等记录持久化并用唯一约束处理并发；密钥轮换、请求超时和重试不重复创建任务或扣额度。
- [ ] 网页、API、MCP 共用全局队列、主体额度与解析限制；一个账户创建多个 Key 不能增加总额度。
- [ ] 资源额度至少覆盖解析请求、任务数、并发、文件大小、处理时间与交付流量；创建时原子预留、收尾时结算，取消和失败的资源仍如实记录。
- [ ] 在现有公网目标与出站代理约束外保留网络侧防护；重定向、DNS 变化、媒体分片和封面等后续请求不能绕过限制。
- [ ] 拒绝任意服务器路径、代理、Cookie、yt-dlp 参数和客户端伪造的 directUrl；参数长度、枚举、大小和超时都有边界。
- [ ] 凭据无效为 401、权限不足为 403；非本人任务与不存在任务对外一致；限流返回 429 与 Retry-After，不暴露内部异常。

**验收：**一份脚本无需浏览器 Cookie 即可完成解析、创建、轮询和取文件；覆盖跨账户越权、过期解析、伪造格式、撤销 Key、并发幂等、超限、断线重试、重启和取消失败。至少完成 local 与 R2 两种存储的授权回归，才能声称两种配置均支持。

### P2-01：在相同业务服务上增加 MCP

**前置：**API 隔离、额度、异步任务和结果语义已经稳定，存在真实自动化使用者。

| 拟新增工具 | 作用 |
| --- | --- |
| `inspect_media` | 查看可用格式、字幕及有效期 |
| `create_download` | 创建任务，立即返回 jobId，说明资源消耗 |
| `get_download` | 查询状态、错误类别及下一步 |
| `get_download_link` | 在授权范围内获取短时交付链接 |
| `cancel_download` | 取消本人任务，明确停止是否已完成 |

- [ ] 工具层只做协议适配，调用与 REST/网页相同的主体、权限、额度和任务服务，不再 spawn 第二套下载逻辑。
- [ ] 公开远程 MCP 采用标准 OAuth 授权、PKCE、同意页、资源受众与 scope 校验，验证令牌刷新及撤销。
- [ ] 受控 API Key 内测仅承诺已验证客户端兼容；不能替代面向通用远程客户端的授权流程。
- [ ] 按实施时官方文档锁定 Better Auth 插件和 MCP SDK 版本；正确挂载发现端点，不让静态页面或匿名会话拦截发现流程。
- [ ] 鉴权插件解决授权，SDK 解决 MCP 协议，任务服务解决业务；不要把安装插件当作下载工具已经实现。
- [ ] 大文件不作为工具文本或 base64 返回；异步状态查询有合理间隔，禁止高频轮询占满服务。
- [ ] 临时链接限定单个文件与短时效，属于 bearer 凭据；不得包含账户 Key，避免进入分析日志。关闭链接签发后现有短链的撤销策略必须有文档。
- [ ] 媒体标题、描述和字幕作为不可信数据，不当作 Agent 指令；创建和取消工具准确标注副作用，由支持的客户端展示确认。
- [ ] 若未来加入 CIMD、发现文档或 JWKS 的远程获取，使用官方安全传输并单独验证 SSRF，不能只依赖视频下载的公网校验。

**验收：**选定至少两种实际目标客户端，记录名称、版本、授权方式及协议版本；测试授权拒绝、过期刷新、撤销、scope 不足、跨账户访问、任务查询和取消。未经测试的客户端不列为兼容。

## 6. 分批发布与继续投入条件

| 批次 | 内容 | 进入下一批的条件 |
| --- | --- | --- |
| A | P0-01、P0-02 | 受控任务能对账，来源与分母明确，统计故障不影响下载 |

| C | P1-02、P1-03 | 隔离、迁移、撤销、幂等与额度测试通过；内测名单和资源预算已经确定 |
| D | P2-01 | 至少有真实自动化使用者，API 能稳定支撑其工作流，目标客户端已选定 |

建议先邀请 5 位有明确工作流的人，由用户确认后再联系。可把“3 位完成真实工作流、其中 2 位在下一周继续使用”作为是否继续投入的产品检查点；这是人为设定的内测目标，不是市场规模、付费意愿或统计显著性的证明。

复盘应同时看完成率、错误构成、排队时长和成本，不只看注册或 Key 创建量。当前样本不足以设定可信的提升百分比，先建立基线再确定目标。

**上线前必须明确的配置：**匿名与账户额度、全局资源预算、API 内测资格、登录渠道、数据保留期与目标 MCP 客户端。未配置额度或资格时，新开发者入口默认关闭，现有网页不因此被强制登录。

**回退：**按网页交互、Auth、API、MCP 分别控制上线。先停止接收受影响的新任务，再等待既有执行、上传和解析收尾；不要直接删工作目录或清空用户数据。关闭 API/MCP 创建入口时保留已授权任务查询与取文件的明确处理策略。增加账户后还需提供隐私说明、账户删除/凭据撤销规则，不能将账户删除误实现为立即删除仍在执行的目录。

## 8. 暂时不做

1. 不把普通网页下载全面改成登录后才能用，也不在默认首屏增加大段注册营销。
2. 不因一日流量峰值推断需求已稳定，不把带 ChatGPT 参数的浏览直接写成官方推荐或 MCP 需求。
3. 不大规模增加语言、关键词页或同义词页面，不购买无法验证效果的 GEO/SEO 承诺。
4. 不实现无限免费 API、任意下载参数、来源 Cookie 托管、批量任务、Webhook 或完整订阅计费。
5. 不重写下载引擎、不另建绕过现有队列的 MCP 下载器、不为接入 Better Auth 更换整个框架。
6. 不把文件生成、保存点击、HTTP 传输结束混称为“用户设备保存成功”，不靠虚构指标证明成果。
