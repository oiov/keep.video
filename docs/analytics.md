# 下载漏斗统计（本地 SQLite）

更新日期：2026-10-27。代码已实现，本地验收不等于已经部署。本文不包含生产原始日志或凭据。

## 1. 数据放在哪里

- **Umami**：继续负责站点访客、PV、访问次数及其自身的来源分析。已有 GA4 保持独立；本次没有把下载事件复制到这两个第三方系统，也没有重复发送 PV。
- **服务端事件**：写入 `DOWNVID_DATA_DIR/analytics/analytics.sqlite`，按 UTC 日期计容量与清理；容器内默认 `/data/userdata/analytics/`，沿用已有持久化卷。使用 Node 22.13+ 内置 SQLite，不需要独立数据库服务。
- **离线报告**：`scripts/analytics-report.ts` 优先读取 SQLite 的只读一致性快照，输出 Markdown、JSON 或指标键值 CSV。无数据库时兼容旧 JSONL，不新增公开统计接口或管理后台。
- 会话、任务与额度位于独立业务库 `DOWNVID_DATA_DIR/state.sqlite`。该库及保留的旧业务 JSON 含任务地址与授权凭据，**不是脱敏统计文件**，不能作为公开报表上传。

这适用于当前单实例服务。多实例调度、计费或可靠审计需要另行设计，不可把该尽力记录的统计库当业务账本。

## 2. 配置与容量

| 变量 | 默认值 | 含义 |
| --- | --- | --- |
| `ANALYTICS_ENABLED` | `1` | `0` 停止新事件；到期旧日志仍清理，不影响下载 |
| `ANALYTICS_ENVIRONMENT` | `development` | 仅允许 `production`、`development`、`test`；生产须显式配置 |
| `ANALYTICS_RETENTION_DAYS` | `30` | 保留 1–30 个 UTC 日分区，含当日；不改变下载文件 TTL |
| `ANALYTICS_MAX_DAILY_MB` | `16` | 每日事件序列化 JSON 加换行的逻辑字节上限，单位 MiB；超过后丢弃事件 |

默认保留事件的逻辑载荷上限约 480 MiB，**不是数据库磁盘体积上限**：SQLite 表、索引、WAL、空闲页及迁移保留的 JSONL 都有额外开销。每日计数持久化，重启不重置。旧日志导入不因新配置变小而丢弃有效历史，该日后续写入仍受新上限约束。启动及每分钟执行清理，禁用采集仍清理旧事件。删除逻辑记录后空闲页复用，数据库不保证立即物理缩小或擦除；备份与人工导出的副本须另行管理保留期。

事件进入有界 1000 条内存缓冲，每批最多 100 条，以独立库短事务写入，批次间让出事件循环；SQLite 调用本身仍为同步，报表在独立 CLI 进程执行。统计写锁等待至多 50ms，不与业务库共用写锁。写入失败时丢弃待写事件并退避 30 秒，下载继续。关闭服务最多等待统计写入 2 秒；异常退出、NORMAL 同步模式、内存上限、每日上限、网络断开均可能丢事件。库内健康状态的 `written`、`dropped`、`writeFailures` 只反映最近进程的尽力记录，状态自身也可能写入失败，不能据其为零证明没有丢失。

## 3. 事件与隐私边界

| 事件 | 记录方与含义 |
| --- | --- |
| `tool_view` | 浏览器初始化工具成功，不是新增 PV |
| `example_selected` | 用户主动选择示例 |
| `parse_rejected` | 服务端限流／繁忙拒绝，独立于已接受解析 |
| `parse_requested` / `parse_finished` | 已接受解析及真实收尾，含安全结果类别与耗时 |
| `job_created` / `job_started` / `job_stage` | 任务持久化成功、开始执行、阶段变化 |
| `job_rejected` | 已有本人有效解析结果，但因队列、格式、累计额度或额度存储问题拒绝创建；不进入已创建任务分母 |
| `job_finished` | 下载与上传实际收尾；区分完成、错误、用户取消 |
| `file_save_clicked` | 点击保存，不等于设备落盘 |
| `file_delivery_finished` | 已授权本人文件的一次 GET/HEAD 响应，含状态、Range 与管道字节 |

统计仅允许时间、环境、`web` 客户端、语言、来源／平台枚举、输入类型、数值耗时／字节、阶段和安全错误码。**不保存完整视频 URL、标题、IP、User-Agent、Cookie、Authorization、API Key、签名链接、文件路径或原始错误输出。** 浏览器只能上报三个交互事件，不能伪造任务成功；服务端仍对白名单字段清洗。客户端来源、语言与测试标记仍可被伪造，不能用于安全判断。

使用独立随机统计会话 ID、解析 ID 和任务 ID；它们不是可访问文件的业务凭据。统计会话 ID 可在同一匿名会话的多次访问间关联，属于**伪名化**，不是不可关联的完全匿名数据；不建立指纹，不与 Umami 身份连接，也不是人数。业务会话表及迁移原件保留凭据与统计 ID 的映射，因此必须保护持久化卷和备份，不能公开或给浏览器读取。

任务生命周期使用稳定事件 ID，离线报告先按环境、测试标记和 asOf 筛选，再按事件 ID 去重。统计表保留收到的重复事件以继续报告 `duplicateEvents`；迁移重放则由文件名／行号唯一约束拦住，不能算作新事件。相同会话和 `clientId` 的重复提交返回原任务，业务库有唯一约束；重新尝试须重新解析并产生新 ID。浏览器交互事件仅做有界、24 小时内存去重，不跨服务重启持久化；前端不重试遥测。关闭网页不停止服务器任务，刷新／重连只恢复列表，不再次创建任务。

### 来源与测试流量

- UTM 与 referrer 各自分类为 `chatgpt/search/social/internal/other/direct_or_unknown`，不保存完整来源地址；冲突单列。
- 来源是**工具页当前上下文**，不是跨页面首次触点归因。没有 referrer 不能自动判为搜索；UTM 标记不证明真实推荐来源。
- `example` / `user_input` / `unknown` 分开展示；手工输入同一内置示例 URL 也归为示例，避免高估真实需求。
- 正式域名之外、预览构建与 `?analytics_test=1` 页面不加载 Umami/GA4。该参数只作用于当前页面；导航后可能丢失，测试生产站每个入口都应带标记。
- 本地验收设置 `ANALYTICS_ENVIRONMENT=test`。默认报告只读 production 且排除测试标记；显式 `--include-tests` 才包含标记事件。已上线旧版收到的访问不能补写为新漏斗。
- 非本地站点启用采集时必须显式设置环境。报表的 `coverage.environmentEventsInWindow` 按事件 ID 去重列出窗口内各环境的数量（不按输入类型筛选），所选环境为空但其他环境有记录时输出警告，不自动把 development 混入生产数据。非生产报告也会提醒无法仅凭测试标记确认真实用户。
- 平台分类仅增加固定枚举及已知短链：Facebook、Pinterest、Reddit、Twitch、Dailymotion、SoundCloud、OK.ru、VK；不记录任意域名、重定向路径或完整 URL。旧日志的 other 不回填、不猜测。
- 真人验证单列 `verification-required`，不再和 `authentication` 混用；会话累计额度拒绝使用 `parse-quota`，与上游 `rate-limit` 分开。`parses.rejections` 包含冷却、额度与繁忙等拒绝类别，拒绝不进入已接受解析成功率分母。
- `jobs.rejections` 单列有效解析后的创建拒绝，包括 `download-quota`；不包含无效或过期解析、服务停止等更早的请求拒绝，不等于所有 RPC 错误数。旧版日志没有该事件时，零值不能证明没有拒绝。

## 4. 指标分母

报告记录带时区的 `[from,to)`、追踪截止 `asOf`、环境、输入筛选和导出时间。解析按接受时间、任务按创建时间入组，追踪到 `asOf`，允许跨日完成。

| 指标 | 定义 |
| --- | --- |
| 解析成功率 | 同批次成功 / 已收尾解析；另列拒绝和仍在执行／缺失 |
| 任务完成率 | 同批次 completed / 已终态；取消纳入终态分母但单列，不并入 error |
| 工具使用率 | 窗口内提交真实链接的可测量会话 / 窗口内有 tool_view 的自有会话 |
| 激活率 | 同批次至少一项真实链接任务完成的会话 / 可测量工具页会话 |
| 会话解析成功率 | 窗口内提交真实链接且至少一次成功的可测量会话 / 提交真实链接的可测量会话 |
| 会话完整响应率 | 窗口内创建的真实任务完成且出现完整 GET 200 的可测量会话 / 工具页会话；追踪到 asOf，不等于设备保存 |
| 耗时 | 排队、解析、下载与合并、上传分别报告样本量、中位数与 P95 |
| 交付 | 按响应发生窗口统计完整 200、206、HEAD、中断、错误与实际管道字节 |

使用率／激活率始终以 `user_input` 计算，独立于 `--input` 对任务、解析与交付明细的筛选。空分母显示 `null`／未知；无终态单列 `queuedOrMissing` / `runningOrMissing`，不得填成失败。终态无起点也单列，可能因为保留期或丢失。

`usage` 额外列出成功解析、创建任务和完整响应的会话数。`parses.sessions` 按所选输入批次统计提交会话、至少一次成功和尚无成功的会话；尚无成功可能包括未收尾，不自动算失败。`breakdown` 同时包含解析与任务结果，因此零任务的平台不会从失败分析中消失。

`parses.concentration` 列出第一／前两个高频会话的请求数及占比，以及排除前两个后的解析成功率敏感性分析。缺失会话标识的请求单列，不参与排名；并列按内部 ID 稳定排序，但输出不包含 ID。敏感性分析不删除原数据，不证明机器人、独立人数或流量真实性。所有会话数量均不是 Umami UV，来源／语言分组也不能相加当作独立会话总数。

完整 HTTP 响应不证明用户设备已保存；多个 Range 不拼成成功文件数；重复保存不等于多个独立任务。交付字节是流经服务端响应管道的字节，含中断前数据，不能替代 CDN／云账单。尚无资源计量和单价，因此 `resourceCost` 为 null，不估算费用。

`delivery.distinctFullResponseJobs` 只对响应发生窗口中的完整 GET 200 按任务 ID 去重，与 `usage` 的创建批次追踪不是同一分母。

## 5. 生成报告

先设置生产环境、部署经过验收的镜像，再开始收集基线；本次不自动执行部署。

```bash
pnpm analytics:report \
  --dir data/userdata/analytics \
  --from 2026-10-23T00:00:00+08:00 \
  --to 2026-10-24T00:00:00+08:00 \
  --as-of 2026-10-24T12:00:00+08:00 \
  --timezone Asia/Shanghai --environment production \
  --input all --format markdown
```

时间仅为命令示例，不能据此声称该窗口已有生产数据。支持 `--format json` / `csv`；CSV 为指标键值表。想单独观察真实链接时使用 `--input user_input`；`--as-of` 不得早于 `--to`。

镜像已包含无额外运行依赖的 CLI：

```bash
docker compose exec -T website node /app/analytics-report.mjs \
  --dir /data/userdata/analytics \
  --from 2026-10-23T00:00:00+08:00 \
  --to 2026-10-24T00:00:00+08:00 \
  --as-of 2026-10-24T12:00:00+08:00 \
  --timezone Asia/Shanghai --environment production --format json
```

可以附加 `--umami <本地导出文件>`，并在已知时补 `--umami-from`、`--umami-to`、`--umami-timezone`、`--umami-exported-at`、`--umami-filters`。缺失元数据保留 null，不根据文件名猜测；`sameWindow` 只检查声明的时间窗口相符，不保证两个系统覆盖人群、筛选或身份相同。

目前 fullPath CSV 仅按 pathname 合并 **PV**，另列 UTM 标记。不能相加页面 UV 或 visits；站点访客、小时趋势、入站页、referrer 须另外导出，本 CLI 不伪造这些字段。历史 34 行导出可复核为 541 PV、英文 `/app/` 373 PV、ChatGPT UTM 标记 336 PV，分组互相包含，不能再次相加。

SQLite 报表使用只读事务，并只把窗口事件及相关实体的前置起点、跨日终态和交付记录交给原有聚合逻辑；整体覆盖数量与环境分布由 SQL 计算，分母不变。快照不包括尚在内存缓冲或尚未提交的事件。`reader.backend` 区分 sqlite/jsonl；`malformedLines` 在 SQLite 模式是迁移时发现的坏行累计，不表示库内存在坏行。

旧 JSONL 导入时逐行白名单清洗，损坏／未写完行跳过并计数，文件与行号检查点支持中断重试；保留原件至原有保留期届满。迁移失败不阻断下载，但迁移未完成不输出部分 SQLite 报表。存在 SQLite 时不叠加读取 JSONL，也不在数据库损坏时静默回退。原始事件已过期时，过去批次不可能完整重建，宜定期保留必要的**聚合**基线并记录其生成时间和缺失情况。

## 6. 验收与回退

- `pnpm test:web` 覆盖会话隔离、Range/HEAD/完整交付、伪造事件、统计限流、幂等、取消、关页后收尾、禁用、容量、轮转及磁盘故障；新增事务迁移与回滚、跨进程额度竞争、统计故障隔离和 36 组 SQLite／旧报表等价回归，保留变异反证。
- `pnpm test` 覆盖来源边界、字段清洗、错误类别、跨日批次、去重、测试排除和缺失值。
- 浏览器真实验收另见 [行动计划实施记录](growth-and-developer-roadmap.md#7-测试与验收记录)。视口模拟不能替代 iOS／Android 真机。
- 停止采集：设 `ANALYTICS_ENABLED=0` 后重新启动服务。仅关闭本地新事件，不自动关闭已有第三方 PV；后者由网站构建配置管理。
- 回退：先停服并等待下载／上传／解析收尾；升级前备份整个卷。旧 JSON 不再双写，回退到文件版必须恢复同批次备份，不能只换镜像或混搭旧额度与新任务。WAL 模式在线备份不能只复制 .sqlite 主文件，详见 [部署与迁移](server-deployment.md#sqlite-与旧数据迁移)。
- 默认不导出原始 JSONL 或数据库到第三方。运营复盘只共享必要聚合；生产上线前确认隐私说明、持久化卷权限及备份保留政策。
